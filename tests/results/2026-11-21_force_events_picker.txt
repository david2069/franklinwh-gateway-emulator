# #374 Web UI: Force events' gateways by filter drop-downs and a multi-select, 2026-11-21

Base: origin/main 31b3a85 (#375, city-level postcodes in the examples). No owner design for this
form in private/ui-design (searched: no Force events or multi-select board); it follows the
gateway picker's filters (#142) and the panel's existing styles.

Design: the "Gateways" fieldset has the picker's filters, reused from groups.js (PICK_FILTERS,
pickField, pickGateways, pickValues; Country, State / province, Postcode, Timezone, in that order,
always shown, `any` by default; the picker's narrowing moved into withFilter(), which the picker
now calls too, unchanged), then a button showing the selection ("All 71 gateways selected",
"20 of 71 gateways selected · 1 hidden by filter", "No gateways selected"). It opens a list of the
gateways the filters match, one checkbox each, scrolling (max-height min(280px, 45vh)), with
"Select all matching (N)" (adds them) and "Clear" (none, hidden ones too). Esc or a click outside
closes it; Esc stops there (the drawer's window Esc handler is not reached) and focus goes back to
the button; opening it focuses "Select all matching". The filters are the form's own, not stored.
The fleet `group` is not a filter: it is not in PICK_FILTERS, so it did not fall out of the code.

"all" and "site": "all" was a checkbox sending targets "all" (the server's every gateway); it is
the default and stays so: the selection is {all: true} at first, and whenever every gateway is
selected again (by ticks or Select all matching with no filter) the form sends targets "all";
otherwise the ids in fleet order. "site" is not special: it is the first gateway's id in
examples/fleet.yaml and fleet-global.yaml ("- id: site"), so it is in the list like any other.
